Ниже — техническое описание приёмов, которые реально читаются по структуре страницы, плюс как это обычно реализуется на фронте (без угадывания конкретных библиотек).

1) Архитектура страницы и навигации

Повторяющийся CTA “Start a project”: в хедере и дальше по странице в ключевых местах, чтобы конверсия не зависела от того, насколько далеко пользователь уже проскроллил.

Лента кейсов как список ссылок: каждая карточка — отдельная ссылка на work.outloud.co/... (по сути, каталог кейс-страниц).

Смешанные статусы “See live / Coming soon”: один и тот же тип карточек, но с разными состояниями (живой проект vs заглушка).

2) Скролл-анимации (ощущение “летает”)
2.1. Reveal-on-scroll (появление блоков при входе в viewport)

Типовой набор:

старт: opacity: 0 + transform: translateY(…)

вход: opacity: 1 + transform: translateY(0)

тайминг: 200–600ms, easing мягкий (например, ease-out)

Технически обычно:

IntersectionObserver (срабатывает, когда секция/карточка попала в экран)

или scroll-timeline/scroll-driven animations (реже, из-за поддержки браузеров)

2.2. Только “дешёвые” свойства

Чтобы 60fps:

анимируют transform/opacity

избегают анимации layout-свойств (top/left/height/width) и тяжёлых фильтров на больших областях

2.3. Лёгкое “скролл-сглаживание”

Эффект “инерции” обычно делается:

либо чисто ощущением от анимаций (элементы догоняют скролл по триггеру)

либо библиотекой smooth scroll, которая делает scroll “плавнее” (важно: это не обязательно, но это частый приём)

3) Lazy-loading медиа и секций (почему быстро)

На странице много изображений и сеток, но ощущение лёгкости достигается тем, что:

изображения подгружаются по мере приближения (lazy-load)

ниже первого экрана контент часто грузят пачками/по секциям

часто используют CDN + современные форматы (webp и т.п.)

Технически:

loading="lazy" / decoding="async" на <img>

IntersectionObserver для “подгрузить, когда близко”

responsive images (srcset/sizes) — чтобы не тянуть огромные файлы на мобилке

4) Кастомный курсор на карточках

То, что тебе понравилось на карточках, обычно реализуют так:

рисуют отдельный DOM-элемент “cursor” (круг/лейбл)

на hover карточки показывают этот элемент

на mousemove обновляют позицию курсора через transform: translate3d(x,y,0)

добавляют небольшое “запаздывание” (lerp), чтобы курсор “плыл”, а не лип к мыши

Ключ: позиционирование через transform, а не через top/left — меньше лагов.

5) Слайдер отзывов

На странице явно есть “Previous/Next slide” и повторяющиеся отзывы.
Технически обычно:

горизонтальная лента (translateX) или fade-переключение

управление кнопками + автопрокрутка (не всегда)

анимации опять же через transform/opacity

6) Переходы цвета фона внизу (то, что ты отметила)

Есть два популярных способа сделать “перетекание” фона:

Вариант A (самый частый и дешёвый): “слои фона”

у секций разные фоновые цвета

между секциями добавляют градиентный переход (полоса/оверлей)

визуально кажется, что фон “перетекает”

Вариант B (более “киношный”): один фон, который анимируется по скроллу

фиксированный фон-слой (например, position: fixed; inset: 0)

поверх него секции прозрачные/полупрозрачные

по скроллу меняют CSS-переменную, например --bg: …, и фон плавно интерполируется

иногда используют blend modes (осторожно с производительностью)

7) Микро-интеракции (hover/focus states)

hover на карточках/ссылках: лёгкие изменения (подчёркивание, opacity, смещение на 2–4px)

единый “темп” анимаций по всему сайту (воспринимается как премиальность)

8) Почему кажется, что “ничего лишнего”

Это тоже технический приём:

минимум тяжёлых эффектов на больших областях (особенно blur/backdrop-filter)

повторяемые компоненты (карточки/секции) → меньше хаоса в DOM → проще оптимизировать

медиа подгружаются позже → быстрый first paint
